# DBService v1.2 快速使用说明

## 引用方式

### 1. 拷贝文件到业务项目

由于 Debug / Release 构建产物不同，需分别放置：

```
业务项目/
├── include/                    ← 拷贝 include/ 目录（Debug/Release 共用）
│   ├── DBService.h
│   ├── DBLogManager.h
│   ├── DBServiceStruct.h
│   ├── DBConfig.h
│   └── dbservice_global.h
├── lib/
│   ├── debug/                  ← 拷贝 Debug DLL + .a
│   │   ├── DBService.dll
│   │   └── libDBService.a
│   └── release/                ← 拷贝 Release DLL + .a
│       ├── DBService.dll
│       └── libDBService.a
└── config/
    ├── DBConfig.ini            ← 数据库配置
    └── LogConfig.ini           ← 日志配置
```

### 2. .pro 文件配置

```pro
INCLUDEPATH += $$PWD/include

# Debug / Release 分开链接
CONFIG(debug, debug|release) {
    LIBS += -L$$PWD/lib/debug -lDBService
} else {
    LIBS += -L$$PWD/lib/release -lDBService
}
```

### 3. 运行时部署

`DBService.dll` 需放在 exe 同级目录。Debug 和 Release 分别使用对应的 DLL。

## 使用示例

### 快速使用（配置文件方式）

```cpp
#include <DBService.h>
#include <DBLogManager.h>

// 1. 从配置文件加载数据库配置
auto config = DBService::loadSimpleConfig("config/DBConfig.ini");

// 2. 创建并初始化 DBService
//    默认 MainThread 模式（旧行为，不传参等效 v1.1）
DBService* db = new DBService(config, this);
//    如需子线程模式（不阻塞 UI）：
// DBService* db = new DBService(config, TaskThreadModel::WorkerThread, this);

// 3. 启动服务
db->start();

// 4. 创建日志管理器并启动
DBLogManager* logMgr = new DBLogManager(this);
logMgr->start("service_log", 30000);

// 5. 连接信号
connect(db, &DBService::sigExecFinished, this, [](const DBServiceResult& result) {
    qDebug() << "执行结果:" << result.isSuccess << result.errorMsg;
});

// 6. 执行 SQL
QVector<SqlTuple> sqlList;
sqlList.append(SqlTuple("INSERT INTO table VALUES (?)", {1}));
db->onExecSqlList(sqlList);
```

### 手动配置方式

```cpp
DBConfig dbConfig;
dbConfig.dbName = "mydb";
dbConfig.host = "127.0.0.1";
dbConfig.port = 3306;
dbConfig.user = "root";
dbConfig.password = "123456";

// Reliable 模式：SQL 正确时 100% 执行，永不丢失
DBService* db = new DBService(DBServiceType::Reliable, dbConfig, this);
db->start();
```

## 服务类型说明

| 类型       | 重试策略        | 适用场景                     |
|------------|----------------|------------------------------|
| Reliable   | ForeverRetry   | 日志/审计等必须落库           |
| HighPerf   | 批量入队+短间隔 | 高频写入（如实时数据采集）     |
| Standard   | 有限重试(3次)   | 通用业务                     |
| Unreliable | NoRetry        | 非关键查询，一次即弃           |

## 线程模式说明

v1.2 新增 `TaskThreadModel` 枚举，允许使用者选择 `DBTaskManager` 的运行线程：

| 模式          | 枚举值                                   | 行为                                              |
|---------------|------------------------------------------|---------------------------------------------------|
| 主线程（默认） | `TaskThreadModel::MainThread`            | TaskManager 在主线程运行，SQL 阻塞会卡 UI          |
| 子线程        | `TaskThreadModel::WorkerThread`          | TaskManager 移入子线程，SQL 阻塞不影响 UI          |

### 选择建议

- **旧项目升级**：不传参或传 `MainThread`，行为与 v1.1 完全一致，零改动
- **新项目 / 有 UI 的项目**：推荐 `WorkerThread`，避免数据库超时导致界面冻结
- **后台无 UI 服务**：`MainThread` 即可，无需额外线程开销

### 注意事项

- `sigExecFinished` 始终在主线程触发（跨线程自动 `QueuedConnection`），槽函数中可直接操作 UI
- `WorkerThread` 模式下，若在 `sigExecFinished` 槽函数中重新投递 SQL，需注意栈深度

## 自定义 taskId

v1.2 提供 `onExecSqlList` 重载，允许调用方传入自定义 `taskId`（如 IPC `requestId`），`DBServiceResult` 原样带回，实现请求-结果精确匹配。

### 使用场景

DBBridgeServer 等框架层需要将 DB 结果映射回具体客户端请求时，不再依赖 `sqlList` 内容硬匹配。

```cpp
// 用 IPC requestId 作为 taskId 投递
QString ipcRequestId = requestObj.value("requestId").toString();
m_dbService->onExecSqlList(sqlList, ipcRequestId);

// sigExecFinished 中精确匹配
connect(db, &DBService::sigExecFinished, this, [](const DBServiceResult& result) {
    if (result.taskId == ipcRequestId) {
        // 精确匹配到请求
    }
});
```

### 与原始版本的关系

| 版本 | 函数签名 | taskId 来源 |
|------|---------|------------|
| v1.1 | `onExecSqlList(sqlList)` | 内部随机 UUID |
| v1.2 | `onExecSqlList(sqlList, taskId)` | 调用方指定 |

原 `onExecSqlList(sqlList)` 完全不变，零影响。

## 原始 JSON 信号

### 问题背景

原有数据流存在 JSON → Qt 类型 → JSON 的无用往返转换：

```
DBTaskResult.resultJson (QJsonDocument)
  → extractData() 拆成 QVector<QVariantMap>  ← 类型信息可能丢失
  → 后端再拼回 QJsonObject                     ← 无用往返
```

`QJsonValue::fromVariant` 不识别 `QVector<QVariantMap>`，数据可能丢失。

### 解决方案

新增 `sigRawResult` 信号，直传原始 `QJsonObject`，跳过 `extractData` 转换：

```cpp
// 连接原始 JSON 信号
connect(db, &DBService::sigRawResult, this, [](const DBServiceRawResult& raw) {
    // raw.resultJson 是原始 QJsonObject，零转换
    QJsonObject data = raw.resultJson;
    // 直接转发到 WebSocket
});

// 结构体字段
// DBServiceRawResult {
//     QString     taskId;        // 任务追踪ID
//     QJsonObject resultJson;    // 原始查询结果JSON
//     bool        isSuccess;     // 执行是否成功
//     int         errCode;       // 错误码
//     QString     errMsg;        // 错误描述
//     QString     errSql;        // 出错SQL
// }
```

### 新数据流

```
DBTaskResult.resultJson (QJsonDocument)
  ↓ sigRawResult（零转换）
WebSocket 响应 (QJsonObject)
```

`sigExecFinished` 保留不删，已有使用者（日志模块等）继续用旧信号，两路信号并存。
