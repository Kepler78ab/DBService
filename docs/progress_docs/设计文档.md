# DBService v1.2 设计文档

> 版本：v1.2.0 | 更新日期：2026-07-27
> 本文档描述 DBService 的架构设计、模块职责和数据流，作为后续版本更新的基准。

## 2. 模块职责

### 2.1 DBService（对外接口层）

对外暴露的入口类。职责：
- 提供 3 种构造方式（空构造、Type+Config、QPair），每种接受 `TaskThreadModel` 参数
- 将 `SqlTuple` 转换为内部 `DBTask` 后投递给 `DBTaskManager`
- 将 `DBTaskResult` 转换为 `DBServiceResult` 返回给业务层（`sigExecFinished`）
- 提供 `sigRawResult` 信号，直传原始 `QJsonObject`，跳过 `extractData` 转换
- 提供 `loadSimpleConfig()` 从 `DBConfig.ini` 加载配置
- 提供 `currentVersion()` 返回当前 DLL 版本号
- 提供 `onExecSqlList(sqlList, taskId)` 重载，支持调用方自定义 taskId
- 根据 `TaskThreadModel` 选择是否将 `DBTaskManager` 移入子线程

### 2.2 DBTaskManager（任务调度层）

异步任务调度核心。职责：
- FIFO 队列串行执行，保证任务顺序
- 三种重试策略：`NoRetry` / `LimitedRetry` / `ForeverRetry`
- 支持批量入队模式：缓冲 → 定时刷新 → 批量入队
- 支持任务延时执行
- 永久性错误判断（SQL 语法错误、重复失败的 SqlUnit）
- WorkerThread 模式下，所有定时器和数据库操作在子线程运行

### 2.3 QDBConnection（数据库连接层）

数据库连接与事务执行。职责：
- 支持 6 种数据库驱动（MySQL / Oracle / ODBC / PostgreSQL / SQLite / DB2）
- 递增连接名策略，避免句柄复用问题
- SELECT 1 心跳检测连接是否存活
- 断线自动重连（有限 / 无限）
- 事务管理：事务开始 → 串行执行 SQL → 提交/回滚

### 2.4 DBLogManager（日志管理层）

独立线程的日志管理。职责：
- 独立工作线程，IO 不阻塞主线程
- 定时刷盘（默认 30 秒一次）
- 按 `serviceName` 分组写入独立文件（`{serviceName}_{yyyyMMdd}.txt`）
- JSON Lines 格式输出
- 空 `serviceName` 默认分组为 `"default"`

## 3. 数据流

### 3.1 MainThread 模式执行流程

```
业务层                          DBService              DBTaskManager        QDBConnection
  │                               │                        │                     │
  │──onExecSqlList(sqlList)──────►│                        │                     │
  │                               │──onPushTask(task)─────►│                     │
  │                               │                        │──execTask(task)────►│
  │                               │                        │                     │──transaction()
  │                               │                        │                     │──executeSqlUnit(unit)
  │                               │                        │                     │──commit()/rollback()
  │                               │                        │◄──DBTaskResult─────│
  │                               │◄──sigTaskComplete(res)─│                     │
  │                               │──convertResult()       │                     │
  │◄──sigExecFinished(result)─────│                        │                     │
```

### 3.2 WorkerThread 模式执行流程

```
业务层（主线程）              DBService（主线程）           工作线程
  │                               │                        │
  │──onExecSqlList(sqlList)──────►│                        │
  │                               │──QMutexLocker          │
  │                               │──m_pendingTasks += sql │
  │                               │──invokeMethod(onPush   │
  │                               │   Task, Queued) ──────►│
  │                               │                        │──pushTask(task)
  │                               │                        │──(SQL 阻塞只卡子线程)
  │                               │                        │──processTask()
  │                               │                        │──execTask(task)
  │                               │                        │──sigTaskComplete(res)
  │                               │◄──(auto QueuedConn)────│
  │                               │──QMutexLocker          │
  │                               │──convertResult()       │
  │◄──sigExecFinished(result)─────│                        │
```

### 3.3 原始 JSON 信号流程（v1.2 新增）

```
DBTaskResult.resultJson  (QJsonDocument)
  onTaskManagerComplete()
    │
    ├── convertResult() → emit sigExecFinished(DBServiceResult)    ← 已有使用者继续用
    │
    └── 构造 DBServiceRawResult
        ├── rawResult.taskId     = result.task.taskId
        ├── rawResult.resultJson = result.resultJson.object()      ← 直传，零转换
        ├── rawResult.isSuccess  = result.isSuccess
        ├── rawResult.errCode    = static_cast<int>(result.errCode)
        ├── rawResult.errMsg     = result.errMsg
        └── rawResult.errSql     = result.errSql
        │
        └── emit sigRawResult(rawResult)                           ← 新信号
              ↓ DBBridgeServer 连接此信号
            WebSocket 响应 (QJsonObject)
```

### 3.4 重试流程

```
processTask()
  ↓ 失败
scheduleRetry()
  ├── NoRetry       → 直接通知失败
  ├── LimitedRetry  → 未超过次数 → 延时重试 | 超过 → 通知失败
  └── ForeverRetry  → 未超最大时长 → 延时重试 | 超时 → 通知失败
  ↓ 重试
onRetryDelayTimeout()
  ↓
processTask() 重新执行
```

### 3.4 日志流程

```
sigExecFinished(result)
  ↓ 业务层接收
记录日志
  ↓ sigRequestRecord (QueuedConnection)
DBLogManager::onRequestRecord()
  ↓ 入队缓冲
m_pendingResults.append(result)
  ↓ 定时触发 (30s)
flushToFile()
  ↓ 分组写入
{serviceName}_{yyyyMMdd}.txt
```

## 4. 核心设计决策

### 4.1 为什么使用 DLL

| 问题 | 方案 |
|------|------|
| 多项目手工复制 DbAccessCustom 导致版本分叉 | DLL 统一版本管理 |
| 业务项目每次改数据库代码需重新编译全部 | DLL 更新，业务项目只需重新链接 |
| 接口变更时难以追踪影响范围 | 稳定接口 + 版本号 + 更新文档追踪 |

### 4.2 为什么 init 失败仍返回 true

电脑重启后数据库服务可能未就绪。`DBService::init` 即使 `DBTaskManager::init` 失败也返回 `true`，原因是：
1. QDBConnection 内部有后台重试机制
2. 信号槽在 init 之前已连接，连接恢复后仍能触发 `sigExecFinished`
3. 否则业务层会因 init 返回 false 中断初始化流程

### 4.3 为什么使用递增连接名

Qt 的 `QSqlDatabase::removeDatabase()` 需要 `QSqlDatabase` 对象完全析构后才能成功。使用固定连接名会导致底层驱动句柄未完全释放时复用旧连接名，引发崩溃。递增计数 + `(quintptr)this` 确保每次连接名唯一。

### 4.4 为什么日志使用独立线程

数据库日志写入是 IO 操作，若在主线程同步写入会阻塞事件循环。DBLogManager 将日志对象移至工作线程，通过 `QueuedConnection` 接收记录请求，定时刷盘不阻塞主线程。

### 4.5 配置缺失可运行

所有配置项的 `.value()` 调用都提供了默认值，即使缺少 `DBConfig.ini` 或 `LogConfig.ini`，模块也能正常初始化，数据库连接会在后台通过重试机制自动恢复。

### 4.6 为什么选择"使用者选择线程模式"而非"强制子线程"

| 方案 | 优点 | 缺点 |
|------|------|------|
| A：强制子线程 | 使用简单，无需理解线程模型 | 无 UI 的后台服务多了无意义的线程切换开销 |
| B：使用者选择 | 灵活，按场景选择最优模式 | 使用者需理解两种模式的差异 |

最终采用方案 B，通过 `TaskThreadModel` 枚举让使用者自行选择：
- 旧项目升级传 `MainThread`（或不传，默认值），零改动
- 有 UI 的项目传 `WorkerThread`，避免阻塞
- 后台服务传 `MainThread`，无额外开销

### 4.7 WorkerThread 关键技术细节

1. **`moveToThread` 前不能有 parent**：`DBTaskManager` 创建时传 `nullptr`，移入线程后再通过 `QThread::finished` 信号自动 `deleteLater`
2. **`QTimer` 自动跟随**：`DBTaskManager` 的四个 QTimer 作为其子对象，随 `moveToThread` 自动移入子线程，无需单独处理
3. **跨线程信号自动 QueuedConnection**：`sigTaskComplete` 从子线程发出，DBService 在主线程接收，Qt 自动使用队列连接
4. **`qRegisterMetaType`**：`DBTask`、`DBTaskResult`、`DBServiceRawResult` 已注册，确保跨线程信号参数正确序列化
5. **`QMutex` 保护 pendingTasks**：主线程写（`onExecSqlList`）与子线程完成信号回主线程读（`onTaskManagerComplete`）存在竞态

### 4.8 为什么新增 sigRawResult 信号（v1.2）

原有数据流存在 JSON → Qt 类型 → JSON 的无用往返转换：

```
DBTaskResult.resultJson (QJsonDocument)
  → extractData() → DBServiceResult.data (QVector<QVariantMap>)
  → QJsonValue::fromVariant → QJsonObject
```

`QJsonValue::fromVariant` 不识别 `QVector<QVariantMap>`，类型信息丢失。`sigRawResult` 信号跳过 `extractData` 转换，直传原始 `QJsonObject`，数据完整性有保障，性能也更高。

`sigExecFinished` 保留不删，日志模块等已有使用者继续用旧信号。两路信号并存。

## 5. 版本号说明

版本格式：`v<主版本>.<次版本>.<修订号>`

| 版本 | 含义 |
|------|------|
| v1.1.x | 内部 bug 修复，接口不变 |
| v1.2.x | 兼容新增能力（线程模式选择） |
| v2.0.x | 破坏性变更 |

- 可通过 `DBService::currentVersion()` 运行时获取
- 每次更新请参考 `update_v<version>.md` 中的更新说明
