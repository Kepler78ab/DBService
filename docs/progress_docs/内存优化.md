# DBService 内存与性能优化方案

> 版本：v2.0 | 日期：2026-07-28
> 本文档分析 DBService 大结果集场景下的内存/CPU 瓶颈，并给出分阶段优化方案。

---

## 一、问题背景

当业务使用 DBService 查询大量数据（万行以上）时，当前数据流存在**多次数据副本**和**无用类型转换**，导致内存占用飙升和 CPU 浪费。

### 核心问题链路（优化前 v1.3.0）

```
MySQL 原始结果
  ↓ executeSqlUnit(): QSqlQuery fetch → QJsonObject × N → QJsonArray
  ↓ execTask(): QJsonDocument(resultObj)
  ↓ sigTaskComplete → DBTaskResult (QJsonDocument 隐式共享)
  ↓
  DBService::onTaskManagerComplete()
    ├── sigRawResult:                                          ← 信号 #1
    │     result.resultJson.object()  →  ★ QJsonObject 深拷贝
    │     emit sigRawResult(DBServiceRawResult)
    │
    └── sigExecFinished:                                       ← 信号 #2
          convertResult()
            └── extractData() → QVector<QVariantMap>   ★ Qt 类型全转换 3~5×
          emit sigExecFinished(DBServiceResult)
```

**关键数据**：一次 1MB 的 JSON 结果：
- 两路信号 = 2 次信号 emit / 2 次结构体 copy
- `extractData` 的 QVariantMap 转换额外吞噬 3~5× 内存
- `resultJson.object()` 深拷贝又 +1×
- 总常驻约 **4~6MB**

---

## 二、优化方案总览

| 优先级 | 优化项 | 类型 | 收益 | 改动量 |
|--------|--------|------|------|--------|
| **P0** | 合并两路信号为一个 `sigExecFinished` | 接口 | -50% 信号开销 | 中 |
| **P0** | `DBServiceResult` 新增 `rawJson`，`extractData` 改为 public static 默认关闭 | 接口 | -3~5× | 中 |
| **P0** | `DBServiceRawResult` 补齐字段，通过 `toRawResult()` 兼容旧调用方 | 结构体 | — | 小 |
| **P0** | `DBServiceRawResult.resultJson`: QJsonObject → QJsonDocument | 结构体 | -1× | 小 |
| **P0** | TaskNode::DBTask 改为 `shared_ptr` | 内部 | 队列积压 ~99% | 小 |
| **P1** | `sigPartialChunk` 分批返回大结果集 | 信号 | 峰值 O(N)→O(batch) | 中 |
| **P2** | 文档引导 + maxResultRows 兜底 | 用户侧 | 源头减少 | 小 |

## 三、P0 — 立即落地

### 3.1 合并信号：去掉 sigRawResult，统一到 sigExecFinished

**改动原因**：当前两路信号在 WorkerThread 模式下产生 2 次跨线程 QueuedConnection 入队和 2 次结构体 copy，增加系统压力。

**改动方案**：
- 移除 `sigRawResult` 信号声明和发射
- `DBServiceResult` 新增 `QJsonDocument rawJson` 字段，携带原始 JSON
- `DBServiceResult` 新增 `toRawResult()` 兼容方法，返回 `DBServiceRawResult`
- `DBServiceRawResult` 补齐缺失字段（`serviceName`、`errTupleIndex`、`DBErrCode`），作兼容结构体保留

**改动后数据流**：

```
onTaskManagerComplete()
  └── convertResult() → 只传 rawJson，不调 extractData
  └── emit sigExecFinished(DBServiceResult)  ← 唯一的信号
        ├── rawJson:    QJsonDocument (原始 JSON，零转换)
        ├── data:       空 (默认不转换)
        ├── serviceName/taskId/sqlList/errXxx:  全量元信息
        └── toRawResult():  → 兼容旧调用方
```

**调用方迁移**：

```cpp
// 旧：单独连接 sigRawResult
connect(db, &DBService::sigRawResult, this, [](const DBServiceRawResult& raw) {
    sendToWebSocket(raw.resultJson);
});

// 新：通过 toRawResult() 一行兼容
connect(db, &DBService::sigExecFinished, this, [](const DBServiceResult& res) {
    auto raw = res.toRawResult();     // ← 拿到完全一样的格式
    sendToWebSocket(raw.resultJson);  // ← 回调内一行不改
});
```

### 3.2 extractData 改为 public static + 默认关闭

**当前问题**：`extractData()` 将原始 JSON 全部转换为 `QMap<QString, QVariant>` + `QVector<QVariantMap>`，这是最大的内存和 CPU 消耗源。且该转换在 `sigExecFinished` 中**强制执行**。

**改动方案**：

| 改动 | 内容 |
|------|------|
| `extractData` | `private` → `public static`，参数改为 `const QJsonDocument&` |
| `DBServiceResult` | 新增 `QJsonDocument rawJson`，`data` 默认空 |
| `convertResult()` | 不再调用 extractData，直接传 rawJson |

**调用方示例**：

```cpp
// 场景 1：不需要结构化数据（网络转发、日志）— 零额外开销
connect(db, &DBService::sigExecFinished, this, [](const DBServiceResult& res) {
    QByteArray bytes = res.rawJson.toJson(QJsonDocument::Compact);
    socket->send(bytes);
});

// 场景 2：需要结构化数据（UI 绑定）
connect(db, &DBService::sigExecFinished, this, [](const DBServiceResult& res) {
    auto data = DBService::extractData(res.rawJson);  // 按需转换
    ui->table->populate(data["users"].value<QVector<QVariantMap>>());
});
```

### 3.3 DBServiceRawResult 补齐字段 + QJsonDocument

**改动**：

```cpp
struct DBServiceRawResult
{
    QString     taskId;
    QString     serviceName;        // ← 新增
    QJsonDocument resultJson;       // ← QJsonObject → QJsonDocument
    bool        isSuccess;
    DBErrCode   errCode;            // ← int → DBErrCode（类型安全）
    QString     errMsg;
    QString     errSql;
    int         errTupleIndex;      // ← 新增
};
```

**改动文件**：

| 文件 | 改动 |
|------|------|
| `include/DBServiceStruct.h` | `DBServiceResult` 升级 + `DBServiceRawResult` 补齐 |
| `include/DBService.h` | 去掉 `sigRawResult`，`extractData` 改 public static |
| `src/DBService/dbservice.h` | 同上 |
| `src/DBService/dbservicestruct.h` | 同 DBServiceStruct.h |
| `src/DBService/dbservice.cpp` | 去掉 sigRawResult emit，convertResult 不调 extractData |

---

### 3.4 TaskNode::DBTask 改为 shared_ptr

**改动**：

```cpp
// 旧：每次入队/出队/重试深拷贝 DBTask（含 QVector<SqlUnit>）
struct TaskNode {
    DBTask    task;
    int       currentRetry;
    // ...
};

// 新：只复制指针，零数据拷贝
struct TaskNode {
    std::shared_ptr<DBTask> task;
    int       currentRetry;
    // ...
};
```

**改动文件**：

| 文件 | 改动 |
|------|------|
| `src/DbAccess/DBTaskManager/dbtaskmanager.h` | `DBTask task` → `std::shared_ptr<DBTask> task` |
| `src/DbAccess/DBTaskManager/dbtaskmanager.cpp` | 所有 `node.task.xxx` → `node.task->xxx` |

---

### 3.5 DBLogManager 适配

DBLogManager::buildJsonLine 当前将 `result.data`（QVariantMap）再转回 JSON，属于无用往返。改为直接读 `result.rawJson`：

```cpp
// 旧：data → QJsonObject 往返转换
QJsonObject dataObj;
for (auto it = result.data.constBegin(); it != result.data.constEnd(); ++it) {
    // ... QVariantMap → QJsonObject 的低效转换
}
obj["data"] = dataObj;

// 新：直接取 rawJson，零转换
if (!result.rawJson.isEmpty()) {
    obj["data"] = result.rawJson.object();
}
```

## 四、P1 — 大结果集分批返回

### 4.1 sigPartialChunk 信号

当查询返回大量行时，边读边发，避免一次性构建完整 QJsonArray。

```cpp
signals:
    void sigPartialChunk(const QString& taskId,
                         const QString& tag,
                         const QJsonArray& rows,
                         int totalRowsSoFar,
                         bool hasMore,
                         bool isSuccess,
                         const QString& errMsg);
```

**DBConfig 新增配置**：
```cpp
int batchResultSize = 0;  // 0=不分批（默认），>0=每批最大行数
```

## 六、优化效果预估

| 场景 | 优化前内存 | 优化后内存 | 提升 |
|------|-----------|-----------|------|
| 1MB 结果，仅信号接收 | ~2MB（双信号） | **~1MB**（单信号 + rawJson） | 50% |
| 1MB 结果，需结构化数据 | ~5MB（强制 extractData） | **~1MB 或按需 +1MB** | 60~80% |
| 100 任务队列积压（各 10 sql） | ~100 份 sqlList 副本 | **1 份 + 99 指针** | ~99% |
